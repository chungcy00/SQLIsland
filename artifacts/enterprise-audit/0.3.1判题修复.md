# 0.3.1 判题复验

0.3.0 上线后的边界复核发现，整数编号、计数及整数金额被提交为带微小小数偏移的数值时，原数值容差比较可能接受错误结果。BP29 的产品编号加 0.005 可以复现。

## 修复与数据来源

从现有公开及隐藏夹具的原始 JSON 数值类型生成逐题整数列策略。汇总同题全部夹具后，具有非空样本且全部为整数的列采用精确比较。出现浮点样本的派生指标继续使用该题原有容差，NULL 与数值继续分开处理。

共覆盖 246 道具有整数输出列的题目。构建时校验夹具 SHA256，夹具发生变化时要求重新生成策略，防止使用过期规则。策略通过构建结果接入实际 Worker 提交判题和结果预测入口。

## 执行结果

- 13 项自动测试通过。
- 全题库参考答案与夹具执行 775 次通过。
- 50 道企业题正确解及等价解执行 408 次通过。
- 在真实 SQLite WASM 中执行 216 条整数列小数偏移错误查询，旧比较器接受 216 条，修复后全部拒绝。
- 有序及无序结果均验证整数精确比较，派生小数容差及超出容差拒绝同时通过。
- 七套数据库的 ERD 元数据复验及浏览器交互复验通过。
- 实际浏览器 Worker 验证 BP29 正确解及等价解各通过 4 套夹具，整数编号偏移错误解被拒绝。
- 数据表单项展开、位置保持、键盘高度记忆和精简标题复验通过。

详细逐项执行结果保存在 `integer-policy-validation.json` 和 `wasm-validation.json`。
