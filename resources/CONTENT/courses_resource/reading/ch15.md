# 第15章 窗口函数

阶段：进阶｜学习目标：保留明细行并完成排名、累计、移动平均与前后期比较。

## kp15-01 OVER 与 PARTITION BY

### 核心概念

普通聚合压缩行数；窗口聚合为每行计算所处窗口的指标。

### 语法

```sql
SUM(v) OVER (PARTITION BY key)
```

### 执行思路

1. 按类别建立窗口
2. 各窗口计算总额
3. 把总额写回每一行

### 示例数据

orders

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### SQL 示例

分析单笔订单在类别中的位置时，同时需要原始行和类别合计。

PARTITION BY 定义窗口范围，OVER 从每条输入行出发补上所在分区的聚合，不压缩成一行一类。

```sql
SELECT id,category,sales,SUM(sales) OVER(PARTITION BY category) AS category_total FROM orders ORDER BY id;
```

### 执行结果

| id | category | sales | category_total |
| --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1400 |
| 2 | 化妆品 | 400 | 700 |
| 3 | 护肤品 | 600 | 1400 |
| 4 | 化妆品 | 300 | 700 |
| 5 | 日用品 | 1500 | 1500 |

护肤品的两行都得到 1400，可继续计算各笔占比；若报表只要各类合计则用 GROUP BY。

### 辨析与易错点

GROUP BY 每组一行，窗口函数保留每条明细。

窗口在行筛选及分组之后计算，不能在同层 WHERE 引用窗口值。

关联题目：q0199、q0200、q0201、q0204

关联闪卡：fc0110、fc0112、fc0119

## kp15-02 ROW_NUMBER、RANK、DENSE_RANK

### 核心概念

ROW_NUMBER 给每行唯一序号；RANK 同值同名次并留空档；DENSE_RANK 同值同名次不留空档。

### 语法

```sql
RANK() OVER(ORDER BY value DESC)
```

### 执行思路

1. 8000排名1
2. 两个5000并列2
3. 3000的普通排名4、密集排名3

### 示例数据

employees

| employee_id | employee_name | manager_id | salary |
| --- | --- | --- | --- |
| 1 | A | NULL | 8000 |
| 2 | B | 1 | 5000 |
| 3 | C | 1 | 5000 |
| 4 | D | 2 | 3000 |

### SQL 示例

排行榜对并列的处理取决于实际规则。

ROW_NUMBER 加唯一决胜键产生连续位置；RANK 并列且跳号；DENSE_RANK 并列但不跳号。不能给后两者加破坏并列的唯一排序键。

```sql
SELECT employee_id,salary,ROW_NUMBER() OVER(ORDER BY salary DESC,employee_id) AS rn,RANK() OVER(ORDER BY salary DESC) AS rnk,DENSE_RANK() OVER(ORDER BY salary DESC) AS dense_rnk FROM employees ORDER BY rn;
```

### 执行结果

| employee_id | salary | rn | rnk | dense_rnk |
| --- | --- | --- | --- | --- |
| 1 | 8000 | 1 | 1 | 1 |
| 2 | 5000 | 2 | 2 | 2 |
| 3 | 5000 | 3 | 2 | 2 |
| 4 | 3000 | 4 | 4 | 3 |

同薪员工可有不同位置编号但相同排名。每组最多三人用 ROW_NUMBER，保留所有并列名次时用 RANK 或 DENSE_RANK。

### 辨析与易错点

唯一序号加编号消除并列不确定性；RANK 不应随意加唯一键破坏并列。

窗口排序并不保证最终输出排序。

关联题目：q0196、q0206、q0207、q0216、q0217、q0218、q0219

关联闪卡：fc0114、fc0115、fc0119

## kp15-03 LAG 与 LEAD

### 核心概念

LAG 获取分区中前一行，LEAD 获取后一行；可指定偏移和缺失默认值。

### 语法

```sql
LAG(v,1) OVER(ORDER BY month)
```

### 执行思路

1. 月份排序
2. 每行读取相邻行指标
3. 边界返回NULL

### 示例数据

monthly

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### SQL 示例

趋势报表需要从相邻记录取上期、下期值。

按月份排序后 LAG 向前取一行、LEAD 向后取一行，边界缺邻居时返回 NULL。先确认月份行连续。

```sql
SELECT month,sales,LAG(sales) OVER(ORDER BY month) AS previous_sales,LEAD(sales) OVER(ORDER BY month) AS next_sales FROM monthly ORDER BY month;
```

### 执行结果

| month | sales | previous_sales | next_sales |
| --- | --- | --- | --- |
| 2026-01 | 1000 | NULL | 1500 |
| 2026-02 | 1500 | 1000 | 1500 |
| 2026-03 | 1500 | 1500 | 900 |
| 2026-04 | 900 | 1500 | NULL |

一月的上期为空，二月上期为 1000。跨门店分析需按门店分区，避免从上一家店取值。

### 辨析与易错点

前一行不一定代表上一个自然月，需先补齐月份。

LAG/LEAD 按排序后的行偏移，不保证恰好是上月或下月；日期缺档需先补齐时间轴。并列排序键应增加稳定决胜键。

关联题目：q0198、q0202、q0209

关联闪卡：fc0113、fc0120

## kp15-04 ROWS、RANGE 与并列累计

### 核心概念

ROWS 按物理窗口行数界定范围；RANGE 按排序值与同值组界定。显式指定累计帧可避免默认帧歧义。

两位员工薪资同为 5,000 时，按薪资的 RANGE 截至当前值会同时计入两位，显示相同累计；ROWS 加员工编号决胜则逐行累加，分别得到 5,000 和 10,000。两列回答的是同薪档累计与逐人累计两个问题。

### 语法

```sql
SUM(v) OVER(ORDER BY key ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
```

### 执行思路

1. 按月份排序
2. 逐行扩大窗口
3. 累计1000、2500、4000、4900

### 示例数据

monthly

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### SQL 示例

累计金额取决于窗口包含哪些行，尤其在同日多笔交易时。

ROWS 从分区首行逐条累加到当前行，若同值行排序不唯一应加决胜键。RANGE 常把排序值相同的行纳入同一批。

**同薪时逐人累计还是同档累计**

第 1、2 行同薪。RANGE 把两行一起计入当前值；ROWS 用 employee_id 拆开同薪，再逐行累计。

```sql
WITH salaries AS (
  SELECT 1 AS employee_id, 5000 AS salary UNION ALL
  SELECT 2, 5000 UNION ALL SELECT 3, 6000
)
SELECT employee_id, salary,
  SUM(salary) OVER (ORDER BY salary RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS range_total,
  SUM(salary) OVER (ORDER BY salary, employee_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS rows_total
FROM salaries ORDER BY salary, employee_id;
```

| employee_id | salary | range_total | rows_total |
| --- | --- | --- | --- |
| 1 | 5000 | 10000 | 5000 |
| 2 | 5000 | 10000 | 10000 |
| 3 | 6000 | 16000 | 16000 |

```sql
SELECT month,sales,SUM(sales) OVER(ORDER BY month ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS cumulative FROM monthly ORDER BY month;
```

### 执行结果

| month | sales | cumulative |
| --- | --- | --- |
| 2026-01 | 1000 | 1000 |
| 2026-02 | 1500 | 2500 |
| 2026-03 | 1500 | 4000 |
| 2026-04 | 900 | 4900 |

前两月累计为 1000 和 2500。若需要逐笔余额，使用 ROWS 并指定稳定顺序；按自然期间看趋势时先汇总。

### 辨析与易错点

存在同值排序键时 RANGE 可能同时纳入所有同值行。

不同分区应添加 PARTITION BY，例如按年份重置累计。

关联题目：q0211、q0212

关联闪卡：fc0116、fc0117

## kp15-05 移动平均与环比

### 核心概念

本例移动平均采用最近三行（含当前行），不足三行取现有行；仅在连续月份数据中才能解释为三个月移动平均。环比仅在上一行确为上月时成立，分母不得为零。

### 语法

```sql
AVG(v) OVER(ORDER BY key ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
```

### 执行思路

1. 按月计算前三行窗口均值
2. 取上期销售
3. 计算环比百分数

### 示例数据

monthly

| month | sales |
| --- | --- |
| 2026-01 | 1000 |
| 2026-02 | 1500 |
| 2026-03 | 1500 |
| 2026-04 | 900 |

### SQL 示例

平滑趋势与识别环比变化可在同一基础月表上完成。

用 ROWS BETWEEN 2 PRECEDING AND CURRENT ROW 得到最多三条记录的平均；LAG 读取上一月，再用 NULLIF 守住零分母。

**逐月补充上期销售与移动平均**

```sql
WITH m AS (SELECT month,sales,LAG(sales) OVER(ORDER BY month) AS prev,AVG(sales) OVER(ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg FROM monthly)
SELECT * FROM m ORDER BY 1, 2, 3, 4 LIMIT 3;
```

| month | sales | prev | moving_avg |
| --- | --- | --- | --- |
| 2026-01 | 1000 | NULL | 1000.0 |
| 2026-02 | 1500 | 1000 | 1250.0 |
| 2026-03 | 1500 | 1500 | 1333.3333333333333 |

```sql
WITH m AS (SELECT month,sales,LAG(sales) OVER(ORDER BY month) AS prev,AVG(sales) OVER(ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg FROM monthly) SELECT month,ROUND(moving_avg,2) AS avg3,ROUND(100.0*(sales-prev)/NULLIF(prev,0),2) AS growth_pct FROM m ORDER BY month;
```

### 执行结果

| month | avg3 | growth_pct |
| --- | --- | --- |
| 2026-01 | 1000.0 | NULL |
| 2026-02 | 1250.0 | 50.0 |
| 2026-03 | 1333.33 | 0.0 |
| 2026-04 | 1300.0 | -40.0 |

第二月的均值是 1250，环比 50%。如业务只接受完整三个月窗口，要先检查框架内的月份数量。

### 辨析与易错点

移动平均是窗口内均值，环比是变化比率。

窗口不足3行时本例按现有行计算；完整3月口径需检查窗口计数。

关联题目：q0203、q0214、q0220

关联闪卡：fc0111、fc0118
