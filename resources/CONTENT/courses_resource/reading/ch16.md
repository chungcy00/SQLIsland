# 第16章 数据清洗

阶段：进阶｜学习目标：识别重复、缺失、异常和格式不一致。

## kp16-01 识别重复与去重规则

### 核心概念

重复记录由业务键决定，不是任意字段相同就删除；先报告重复，再确定保留规则。

### 语法

```sql
GROUP BY business_key HAVING COUNT(*)>1
```

### 执行思路

1. 统一名称与分类
2. 按名称、金额及类别分组
3. 标记重复组

### 示例数据

raw_data

| id | name | amount | category |
| --- | --- | --- | --- |
| 1 |   Mask  | 15 | SKIN |
| 2 | Mask | 15 | skin |
| 3 | Serum | NULL | Skin |
| 4 | Soap | -5 | HOME |
| 5 | Cream | 0 | makeup |

### SQL 示例

先量化疑似重复，再决定哪些记录允许归并。

按清洗后的名称、金额及类别分组，HAVING 筛选计数超过一的组合。这样的组合是待复核的业务键。

```sql
SELECT TRIM(name) AS clean_name,amount,LOWER(category) AS clean_category,COUNT(*) AS duplicate_count FROM raw_data GROUP BY TRIM(name),amount,LOWER(category) HAVING COUNT(*)>1;
```

### 执行结果

| clean_name | amount | clean_category | duplicate_count |
| --- | --- | --- | --- |
| Mask | 15 | skin | 2 |

两条 Mask 被归为一组。若同值交易确实可能多次发生，应加发票号等业务标识或人工复核。

### 辨析与易错点

DISTINCT 能去掉投影后的重复行，但不能决定保留哪一条业务记录。

相同商品和金额可能是合法交易；本例只标记疑似重复。

关联题目：q0221、q0227、q0229

关联闪卡：fc0121、fc0122、fc0126

## kp16-02 缺失与异常检测

### 核心概念

先定义规则，再标记异常；空字符串、NULL、负值及零值有不同含义。

### 语法

```sql
CASE WHEN condition THEN label ... END
```

### 执行思路

1. 先检查名称
2. 检查金额缺失
3. 在已知合法数字文本中识别负值

### 示例数据

raw_data

| id | name | amount | category |
| --- | --- | --- | --- |
| 1 |   Mask  | 15 | SKIN |
| 2 | Mask | 15 | skin |
| 3 | Serum | NULL | Skin |
| 4 | Soap | -5 | HOME |
| 5 | Cream | 0 | makeup |

### SQL 示例

数据质量报告要区分缺失、异常和通过的记录。

CASE 优先检查缺失和全空白文本，然后才比较转换后的金额。用稳定主键保留可回查线索。

```sql
SELECT id,CASE WHEN name IS NULL OR TRIM(name)='' THEN '名称缺失' WHEN amount IS NULL THEN '金额缺失' WHEN CAST(amount AS DECIMAL(12,2))<0 THEN '负金额待核' ELSE '通过' END AS quality FROM raw_data ORDER BY id;
```

### 执行结果

| id | quality |
| --- | --- |
| 1 | 通过 |
| 2 | 通过 |
| 3 | 金额缺失 |
| 4 | 负金额待核 |
| 5 | 通过 |
| 6 | 名称缺失 |

同样的检查可批量汇总每种异常类型。存在非法数字字符串时应先验证可转换性，不能依赖数据库隐式转换。

### 辨析与易错点

异常值不是必然错误，例如退款可以为负数。

样例金额文本已知合法；实际导入必须先验证数字格式。

关联题目：q0222、q0223

关联闪卡：fc0123、fc0127

## kp16-03 CAST 与分类标准化

### 核心概念

CAST 显式转换类型；先清理空白和格式，再验证合法性并转换，最后统一类别。

### 语法

```sql
CAST(expr AS DECIMAL(12,2))
```

### 执行思路

1. 确认输入为数字文本或NULL
2. 转换数值
3. 按映射统一类别

### 示例数据

raw_data

| id | name | amount | category |
| --- | --- | --- | --- |
| 1 |   Mask  | 15 | SKIN |
| 2 | Mask | 15 | skin |
| 3 | Serum | NULL | Skin |
| 4 | Soap | -5 | HOME |
| 5 | Cream | 0 | makeup |

### SQL 示例

不同来源的金额文本及类别写法需要转成统一的对账口径。

CAST 为金额指定目标类型，TRIM 与 LOWER 归一类别后用 CASE 映射。建议保留原字段以便回溯。

```sql
SELECT id,CAST(amount AS DECIMAL(12,2)) AS numeric_amount,CASE WHEN LOWER(TRIM(category))='skin' THEN '护肤品' WHEN LOWER(TRIM(category))='home' THEN '日用品' WHEN LOWER(TRIM(category))='makeup' THEN '化妆品' ELSE '待分类' END AS clean_category FROM raw_data ORDER BY id;
```

### 执行结果

| id | numeric_amount | clean_category |
| --- | --- | --- |
| 1 | 15 | 护肤品 |
| 2 | 15 | 护肤品 |
| 3 | NULL | 护肤品 |
| 4 | -5 | 日用品 |
| 5 | 0 | 化妆品 |
| 6 | 20 | 日用品 |

两种写法可映射为同一数值和类别，行粒度保持不变。遇到无法识别的类别，应按明确规则标记。

### 辨析与易错点

CAST 改变表达式类型，不代表已修改源数据。

本例数字为整数；SQLite DECIMAL 不提供 MySQL 精确十进制保障。

关联题目：q0224、q0226、q0230

关联闪卡：fc0124、fc0125
