## kp19-01 零售：净销售额与门店汇总

### 核心概念

每门店一行；有效线下订单，按原订单日期归属截至年底退货；毛利=净销售-退货冲减后成本；毛利率和目标达成率使用百分比，分母为0返回NULL；金额单位分。保留无销售门店。

要解释门店未达标的原因，可把有效净销售拆到门店×商品类别，用商品类别键连接后再汇总。年度门店目标没有类别粒度，连接到类别明细会把同一目标重复分配。

按 2025 年原订单日期归属线下 completed 销售，退款截止 12 月 31 日。毛利为净销售减退货冲减后成本，毛利率除以净销售，目标达成率除以同期门店目标；任一分母为零时保留 NULL。

### 执行思路

1. 先按门店聚合销售与成本
2. 独立累计目标
3. 左连接门店
4. 计算比率

## kp19-02 库存：快照与周转率

### 核心概念

2025年：净销售出库成本含退货冲回；年初价值以2024-12-31快照、年末以2025-12-31快照；平均库存=两端均值；周转天数365/周转率，销售成本非正时天数NULL。 缺失任一商品的期初或期末快照时，该仓库类别的平均库存及周转指标返回NULL，不将缺失当作零。

先保存每个商品的快照数量及同一成本口径，再累加数量×单位成本得到仓库类别价值。售价和采购成本量纲虽都是金额，不能把售价乘数量后当库存成本。

2025 年以 2024-12-31 和 2025-12-31 两端快照均值作分母，出库成本需冲回退货。缺失必要快照时不算周转率；销售成本非正时周转天数留空，正常情况下用 365 除以周转率。

### 执行思路

1. 分别汇总期间净成本和两端快照
2. 连接相同粒度
3. 计算比例及周转天数

### SQL 示例

电商运营用复购率判断发生有效购买的客户是否再次购买。

**每位客户的有效购买订单数**

```sql
WITH purchases AS (
  SELECT c.customer_id, COUNT(DISTINCT o.order_id) purchase_count
  FROM customers c JOIN v_order_net o ON o.customer_id=c.customer_id
  WHERE o.channel='online' AND o.order_date BETWEEN '2025-01-01' AND '2025-12-31'
    AND o.net_cents>0
  GROUP BY c.customer_id
)
SELECT * FROM purchases ORDER BY 1, 2 LIMIT 3;
```

| --- | --- |
| 1 | 2 |
| 2 | 1 |

```sql
WITH purchases AS (
  SELECT c.customer_id, COUNT(DISTINCT o.order_id) purchase_count
  FROM customers c JOIN v_order_net o ON o.customer_id=c.customer_id
  WHERE o.channel='online' AND o.order_date BETWEEN '2025-01-01' AND '2025-12-31'
    AND o.net_cents>0
  GROUP BY c.customer_id
)
SELECT COUNT(*) AS purchasing_customers,
  COALESCE(SUM(CASE WHEN purchase_count>=2 THEN 1 ELSE 0 END),0) AS repeat_customers,
  ROUND(100.0*COALESCE(SUM(CASE WHEN purchase_count>=2 THEN 1 ELSE 0 END),0)/NULLIF(COUNT(*),0),2) AS repeat_pct
FROM purchases
```

## kp19-32 门店月度环比同比与持续下滑

### 核心概念

构造2023—2025完整门店月份轴；2025年逐月返回净销售、环比、同比及连续三月负增长标志；上期零或缺失时比率NULL。

环比是（本月净额−上月净额）÷上月净额。月份轴先补齐再用 LAG，上月确有零销售、缺少历史或无从定义分母，都不能把增长率显示成 0%。

财务收入趋势可以复用连续月轴和窗口逻辑，金额源要改为入账收入并按入账日期汇总；它与订单日期归属的零售净额可能跨月，比较前先统一口径。

### 执行思路

1. 构造月份轴
2. 汇总销售并补零
3. 计算两个历史窗口
4. 滚动检查连续下滑
5. 最后筛2025

## kp19-36 低销量高库存诊断

2025年每部门每月真实离职人数（终止日期落月内，取终止前岗位）/期初期末平均在职数；期初以当月首日之前一天在职为准；滚动三月率用离职总数/三个月平均人数之和，非简单平均。 三个月滚动指标包含2024年11—12月历史后再筛选2025年输出，不在年度边界重新开始累计；确实不足三个月时返回NULL。

指定日期的在职区间是入职日不晚于该日，且终止日为空或晚于该日。终止当天不在职，使同一份任职记录在连续日期上的状态一致。

期间离职率用真实离职事件数除以期初、期末平均在职人数。部门调离会影响两端人数，但调动不是企业离职，不能混入离职分子。

部门月末净变化可用本月月末人数减上月月末人数，任职历史按左闭右开区间匹配。要查看 2025 年 1 月变化，先保留 2024 年 12 月基线再过滤输出。

1. 从历史岗位重建人数
2. 匹配真正终止
3. 计算月率及加权滚动率

## kp19-57 供应商准时、完整交付与质量

1. 独立按发票日期汇总截止日开票行
2. 连接已预聚合的采购和合格收货
3. 比较订购收货开票数量与金额

### SQL 示例

批准付款前，采购控制员要确认采购量、接收量、开票量和金额能互相解释。

收货与发票独立汇总到采购行后连接，以接受量和约定单价计算应付参考额，保留无收货或无发票的采购行。

**统一采购行的开票数量和金额**

```sql
WITH billed AS (
  SELECT x.po_item_id,SUM(x.quantity_billed) billed,SUM(x.quantity_billed*x.unit_price_cents) billed_cents
  FROM supplier_invoice_items x JOIN supplier_invoices f ON f.supplier_invoice_id=x.supplier_invoice_id
  WHERE f.invoice_date<='2025-12-31' GROUP BY x.po_item_id
)
SELECT * FROM billed ORDER BY 1, 2, 3 LIMIT 3;
```

**连接订购、收货与发票**

```sql
WITH billed AS (
  SELECT x.po_item_id,SUM(x.quantity_billed) billed,SUM(x.quantity_billed*x.unit_price_cents) billed_cents
  FROM supplier_invoice_items x JOIN supplier_invoices f ON f.supplier_invoice_id=x.supplier_invoice_id
  WHERE f.invoice_date<='2025-12-31' GROUP BY x.po_item_id
), checked AS (
  SELECT v.po_item_id,v.po_id,v.supplier_id,v.product_id,v.quantity_ordered,v.accepted,
    COALESCE(b.billed,0) billed,COALESCE(b.billed_cents,0) billed_cents,v.accepted*v.unit_price_cents expected_cents
  FROM v_po_lines v LEFT JOIN billed b ON b.po_item_id=v.po_item_id
  WHERE v.order_date BETWEEN '2025-01-01' AND '2025-12-31'
)
SELECT * FROM checked ORDER BY 1, 2, 3, 4, 5, 6, 7, 8, 9 LIMIT 3;
```

```sql
  FROM v_po_lines v LEFT JOIN billed b ON b.po_item_id=v.po_item_id

SELECT po_item_id,po_id,supplier_id,product_id,quantity_ordered,accepted,billed,billed_cents,expected_cents,

```
