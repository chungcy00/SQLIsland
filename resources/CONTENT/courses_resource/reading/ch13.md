# 第13章 集合运算

阶段：进阶｜学习目标：合并结果集并掌握去重、交集与差集。

## kp13-01 UNION 与 UNION ALL

### 核心概念

UNION 合并并去重，UNION ALL 保留所有行及重复项；两侧必须具有相同列数。

### 语法

```sql
SELECT col FROM a UNION [ALL] SELECT col FROM b ORDER BY col;
```

### 执行思路

1. 读取两批客户
2. 追加所有行
3. 对联合结果排序

### 示例数据

old_customers

| customer_id |
| --- |
| 1 |
| 2 |
| 2 |
| 3 |

new_customers

| customer_id |
| --- |
| 2 |
| 3 |
| 4 |

### SQL 示例

合并两批客户记录时，先区分要保留来源重复还是只要客户清单。

UNION ALL 保留重叠，UNION 对整行做去重。参与合并的列要同序、同含义；最终排序写在最后。

```sql
SELECT customer_id FROM old_customers UNION ALL SELECT customer_id FROM new_customers ORDER BY customer_id;
```

### 执行结果

| customer_id |
| --- |
| 1 |
| 2 |
| 2 |
| 2 |
| 3 |
| 3 |
| 4 |

同一编号在两边出现时，本例保留两行。若要模拟双侧保留的对账，将匹配和单侧未匹配拆开后用 UNION ALL 拼接。

### 辨析与易错点

JOIN 横向组合列，UNION 纵向组合行。

列名通常取第一查询；类型应语义一致，MySQL 与 SQLite 的隐式类型不同。

关联题目：q0176、q0179、q0181、q0182

关联闪卡：fc0096、fc0097、fc0098、fc0102

## kp13-02 INTERSECT 与 EXCEPT

### 核心概念

MySQL 8.4 支持 INTERSECT 求交集，EXCEPT 求前一集合减后一集合，默认去重。

### 语法

```sql
SELECT col FROM a INTERSECT SELECT col FROM b; SELECT col FROM a EXCEPT SELECT col FROM b;
```

### 执行思路

1. 两侧去重
2. 保留共有编号2和3
3. 排序

### 示例数据

old_customers

| customer_id |
| --- |
| 1 |
| 2 |
| 2 |
| 3 |

new_customers

| customer_id |
| --- |
| 2 |
| 3 |
| 4 |

### SQL 示例

比较两个时期或来源的客户集合。

INTERSECT 返回双方都存在的编号，EXCEPT 返回仅左侧存在的编号；也可用 EXISTS 或 NOT EXISTS 按键表达。集合结果的整体 ORDER BY 写在最后；需要先限制某个输入集时，用子查询封装该分支。

```sql
SELECT customer_id FROM old_customers INTERSECT SELECT customer_id FROM new_customers ORDER BY customer_id;
```

### 执行结果

| customer_id |
| --- |
| 2 |
| 3 |

共有客户为 2 和 3；互换 EXCEPT 两侧会改变结果。核对客户迁入迁出时分别运行两个方向。

### 辨析与易错点

EXCEPT 的顺序有意义；INTERSECT 对称。

MySQL 支持 ALL 形式而 SQLite 不支持 INTERSECT ALL / EXCEPT ALL；混合运算优先级亦不同。

关联题目：q0177、q0178

关联闪卡：fc0099、fc0100、fc0101
