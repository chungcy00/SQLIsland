# 第11章 字符串处理

阶段：进阶｜学习目标：掌握文本提取、拼接、清洗及长度计算。

## kp11-01 CONCAT 字符串拼接

### 核心概念

将多个字符串按给定次序连接，MySQL CONCAT 任一参数为 NULL 时返回 NULL。

### 语法

```sql
CONCAT(str1,str2,...)
```

### 执行思路

1. 读取类别和商品名
2. 在中间添加分隔符
3. 拼成标签

### 示例数据

products

| product_id | product_name | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | Mask | 护肤品 | 15 | 150 |
| 2 | Serum | 护肤品 | 89 | 40 |
| 3 | Cleanser | 护肤品 | 35 | 200 |
| 4 | Cream | 化妆品 | 65 | 180 |
| 5 | Sunscreen | 化妆品 | 45 | 80 |

### SQL 示例

报表需要把类别与商品名组合成可读标签。

CONCAT 显式插入分隔符，顺序决定标签结构。MySQL 中空值会传递，需保留部分文本时先约定 COALESCE 的备用值。

```sql
SELECT product_id, CONCAT(category, ' - ', product_name) AS label FROM products ORDER BY product_id;
```

### 执行结果

| product_id | label |
| --- | --- |
| 1 | 护肤品 - Mask |
| 2 | 护肤品 - Serum |
| 3 | 护肤品 - Cleanser |
| 4 | 化妆品 - Cream |
| 5 | 化妆品 - Sunscreen |
| 6 | 日用品 - Soap_1 |

得到如“护肤品 - Mask”的新列，仍是一商品一行。也能用于码表显示，原始键应单独保留供连接。

### 辨析与易错点

SQLite 的 concat 函数会跳过 NULL；|| 遇 NULL 返回 NULL，且 MySQL 默认 || 表示逻辑 OR。

本例仅非空文本；转换需保留 MySQL 的 NULL 语义。

关联题目：q0158

关联闪卡：fc0080

## kp11-02 文本截取、字符数与字节数

### 核心概念

从指定字符位置开始截取，位置从1开始；长度表示截取字符数。

字符限制用 CHAR_LENGTH，接口字节预算在 MySQL 中用 LENGTH。以 UTF-8 的“古晋”为例，2 个字符占 6 字节；SQLite 对 TEXT 的 length 数字符，转成 BLOB 后才数编码字节。

### 语法

```sql
SUBSTRING(str,pos,len)
```

### 执行思路

1. 从名称首字符开始
2. 取最多3个字符

### 示例数据

products

| product_id | product_name | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | Mask | 护肤品 | 15 | 150 |
| 2 | Serum | 护肤品 | 89 | 40 |
| 3 | Cleanser | 护肤品 | 35 | 200 |
| 4 | Cream | 化妆品 | 65 | 180 |
| 5 | Sunscreen | 化妆品 | 45 | 80 |

### SQL 示例

编码前缀要按字符位置提取，不能凭样例结果硬截固定字节。

SUBSTRING 从第一个字符起取三个字符，适合固定长度前缀；分隔符位置变化时先定位再截取。CHAR_LENGTH 计算字符数，LENGTH 在 MySQL 中计算字节数；多字节商品名应按字符截取。

**同一名称的字符数与字节数**

条件是 UTF-8 编码。SQLite 中转为 BLOB 可核对字节长度；MySQL 使用 CHAR_LENGTH 数字符，LENGTH 数字节。

```sql
SELECT LENGTH('古晋') AS character_count,
  LENGTH(CAST('古晋' AS BLOB)) AS byte_count;
```

| character_count | byte_count |
| --- | --- |
| 2 | 6 |

```sql
SELECT product_id, SUBSTRING(product_name,1,3) AS prefix FROM products ORDER BY product_id;
```

### 执行结果

| product_id | prefix |
| --- | --- |
| 1 | Mas |
| 2 | Ser |
| 3 | Cle |
| 4 | Cre |
| 5 | Sun |
| 6 | Soa |

Mask 取 Mas，Serum 取 Ser。分组使用前缀前应检查是否把不同业务含义的编码误合并。

### 辨析与易错点

截取字符串不等于按分隔符拆分。

负位置、零位置以及字符集差异需要单独验证。

关联题目：q0155、q0156

关联闪卡：fc0079、fc0081、fc0084

## kp11-03 TRIM、REPLACE 与大小写

### 核心概念

TRIM 默认去除两端空格；REPLACE 替换匹配子串；LOWER/UPPER 转换大小写。

### 语法

```sql
LOWER(TRIM(str)); REPLACE(str, old, new)
```

### 执行思路

1. 去除名称两端空格
2. 统一类别大小写
3. 演示删除所有普通空格

### 示例数据

raw_data

| id | name | amount | category |
| --- | --- | --- | --- |
| 1 |   Mask  | 15 | SKIN |
| 2 | Mask | 15 | skin |
| 3 | Serum | NULL | Skin |
| 4 | Soap | -5 | HOME |
| 5 | Cream | 0 | makeup |

### SQL 示例

来源系统书写不一致时，在匹配前先统一清洗规则。

TRIM 删边缘空白，LOWER 归一大小写，REPLACE 按明确的字符替换；每者处理不同问题。

```sql
SELECT id, TRIM(name) AS clean_name, LOWER(category) AS clean_category, REPLACE(name,' ','') AS no_spaces FROM raw_data ORDER BY id;
```

### 执行结果

| id | clean_name | clean_category | no_spaces |
| --- | --- | --- | --- |
| 1 | Mask | skin | Mask |
| 2 | Mask | skin | Mask |
| 3 | Serum | skin | Serum |
| 4 | Soap | home | Soap |
| 5 | Cream | makeup | Cream |
| 6 |  | home |  |

前两行清洗后名字和类别相同，为后续重复审查提供候选。空白可能有业务含义，不能无条件删除所有内部空格。

### 辨析与易错点

TRIM 不删除内部空格；REPLACE 可删除内部空格。

Unicode 大小写及特殊空白符涉及字符集；本例大小写仅ASCII。

关联题目：q0151、q0154、q0159

关联闪卡：fc0082、fc0083、fc0085
