# 第05章 空值处理

阶段：入门｜学习目标：区分缺失与零并正确处理三值逻辑。

## kp05-01 空值判断与三值逻辑

### 学习目标

能够区分未知值、零与空字符串，并正确筛选缺失、已知以及明确不等于指定值的记录。

### 核心概念

NULL 表示未知或缺失，不是数字0，也不是长度为零的文本。普通比较例如 value = 10 或 value <> 10，遇到 NULL 通常得到未知，而不是假。SQL 的条件判断采用真、假、未知三种逻辑值；WHERE 只保留真，因此未知记录会被排除。判断缺失要用 IS NULL，判断已知要用 IS NOT NULL。NOT 不会让未知变成真。业务上缺失不一定是错误：订单客户外键为空可能意味着允许访客购买，也可能是数据遗漏，须结合业务规则判定。计数非空字段会跳过缺失，与总记录数不同。

### 语法

```sql
WHERE column_name IS NULL;
WHERE column_name IS NOT NULL;
```

- IS NULL：检查字段是否为空值

- IS NOT NULL：检查字段是否已有值

- <>：不等于，普通比较遇空值为未知

### 执行思路

1. 比较数值与10

2. 排除未知及等于10的记录

3. 单独检查缺失记录

### 示例数据

**nullable_values**

| id | value | note |

| --- | --- | --- |

| 1 | NULL | NULL |

| 2 | 0 | 空字符串 |

| 3 | 10 | ok |

| 4 | 10 | ok |

**orders**

| id | category | sales | store_id | order_date | customer_id |

| --- | --- | --- | --- | --- | --- |

| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |

| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |

| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |

| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |

| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### 代码示例

数据质量人员要筛选明确不等于10的记录，同时单独登记缺失值。不能将未知值自动视作异常数值或实际零。

逐行比较 value 与10：第一行未知，第二行0不等于10，第三和第四行等于10。只有第二行满足 WHERE。若任务要求找缺失记录，则改为 IS NULL；需要同时返回已知不等于10和未知记录，就用 OR 将两种条件明确连接。示例中的 note 空字符串仍是已知文本。

**原有主示例**



```sql
SELECT id, value FROM nullable_values WHERE value <> 10 ORDER BY id;
```

| id | value |

| --- | --- |

| 2 | 0 |

**合并来源：识别缺失记录**

仅返回真正的空值记录。

```sql
SELECT id, value, note FROM nullable_values WHERE value IS NULL ORDER BY id;
```

| id | value | note |

| --- | --- | --- |

| 1 | NULL | NULL |

**同时筛选未知和非10**

显式保留未知值，不依赖普通比较。

```sql
SELECT id,value FROM nullable_values WHERE value <> 10 OR value IS NULL ORDER BY id;
```

| id | value |

| --- | --- |

| 1 | NULL |

| 2 | 0 |

**识别缺少客户编号的订单**

作为匿名订单或数据缺失的待核记录，不直接认定错误。

```sql
SELECT id,customer_id FROM orders WHERE customer_id IS NULL ORDER BY id;
```

| id | customer_id |

| --- | --- |

| 4 | NULL |

### 查询结果

主查询仅返回编号2、值0。缺失检查仅返回编号1；合并条件则返回编号1和2。由此可见，排除10不等于找出所有不是已知10的记录。

### 辨析与易错点

NULL、0与空字符串不同；NOT(value=10) 不会自动包含 NULL。

错误：WHERE value = NULL，或认为 WHERE value <> 10 自动包含缺失行。

修正：使用 IS NULL 检测缺失；若需要两类记录，使用 WHERE value <> 10 OR value IS NULL。

是否将匿名订单或缺失值列入指标，需要明确数据口径。

## kp05-02 空值替换与候选值选择

### 学习目标

能够使用双参数空值替换及多候选值函数，保留真实的零与空字符串，并明确填补规则。

### 核心概念

报表常需为缺失字段提供显示用替代值。IFNULL 接受两个参数：第一个非空时直接返回，否则返回第二个。COALESCE 按顺序返回第一个非空候选值，适合多个候选来源。若所有候选均为空，结果仍为空。零和空字符串不是 NULL，因此不会被这两个函数替换。替代值仅是报表处理规则，不代表原始缺失真实变成了零或其他值。若业务明确把空文本也视为缺失，可先使用 NULLIF 将其转换为空值，再选择替代文本。

### 语法

```sql
IFNULL(a, b);
COALESCE(a, b, c);
```

- a：优先使用的原始值

- b, c：依业务优先级排列的备用值

### 执行思路

1. 检查原始字段

2. 为缺失值选择替代项

3. 保留零及空文本

### 示例数据

**nullable_values**

| id | value | note |

| --- | --- | --- |

| 1 | NULL | NULL |

| 2 | 0 | 空字符串 |

| 3 | 10 | ok |

| 4 | 10 | ok |

### 代码示例

主管希望报表醒目标记未填写的数值与备注，同时不丢失实际零值。示例约定数值缺失显示-1、备注缺失显示 missing；这些仅为展示标记。

IFNULL 检查 value，只有为空才输出-1；COALESCE 检查 note，已有内容即返回原值，否则返回缺失标记。AS 命名展示列。此处只在 SELECT 中转换，不修改原始表。若-1本身可能是合法数值，应另设缺失标识，避免混淆。

**原有主示例**



```sql
SELECT id, IFNULL(value, -1) AS filled, COALESCE(note, 'missing') AS note_filled FROM nullable_values ORDER BY id;
```

| id | filled | note_filled |

| --- | --- | --- |

| 1 | -1 | missing |

| 2 | 0 | 空字符串 |

| 3 | 10 | ok |

| 4 | 10 | ok |

**将空文本按业务规则视作缺失**

仅当业务确认空文本无有效含义时使用；编号2也显示缺失标记。

```sql
SELECT id, COALESCE(NULLIF(note, ''), 'missing') AS note_filled FROM nullable_values ORDER BY id;
```

| id | note_filled |

| --- | --- |

| 1 | missing |

| 2 | missing |

| 3 | ok |

| 4 | ok |

### 查询结果

编号1显示-1及 missing；编号2仍显示0与空字符串；编号3和4仍显示10与 ok。所有四行保留，粒度不变。替换后的列不应直接用于金额汇总。

### 辨析与易错点

IFNULL 固定两个参数；COALESCE 支持多个候选值。两者都不会自动将空文本视作缺失。

错误：COALESCE(value,0) 后认为所有缺失记录原本都是真实零。

修正：先确定业务规则，保留原列或缺失标记；需要将空文本视为缺失时使用 NULLIF。

混合参数类型在 MySQL 与 SQLite 中可能有不同类型推断。本例仅验证所示数据。
