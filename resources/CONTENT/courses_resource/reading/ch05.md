# 第05章 空值处理

阶段：入门｜学习目标：区分缺失与零并正确处理三值逻辑。

## kp05-01 IS NULL 与三值逻辑

### 核心概念

比较未知值通常返回 UNKNOWN，WHERE 只保留 TRUE；IS NULL 专门检测缺失。

订单的客户外键为空时，可能是允许匿名下单的业务规则。用 IS NULL 找出这批记录后，再结合状态或来源判断是否缺报；只检查 COUNT(customer_id) 会跳过它们。

### 语法

```sql
WHERE col IS NULL; WHERE col IS NOT NULL;
```

### 执行思路

1. 比较值与10
2. 未知值不通过
3. 保留零值

### 示例数据

nullable_values

| id | value | note |
| --- | --- | --- |
| 1 | NULL | NULL |
| 2 | 0 |  |
| 3 | 10 | ok |
| 4 | 10 | ok |

### SQL 示例

判断已知数值与筛出缺失是两件不同的工作，质量报表要分别统计。

与 NULL 做普通比较时得到 UNKNOWN，WHERE 只留下 TRUE。要显式选缺失写 IS NULL，要确认存在用 IS NOT NULL。

**单独找出不知道的值**

普通比较会跳过缺失行。换成 IS NULL 明确选择缺失，0 仍留在已知记录中。

```sql
SELECT id, value, note FROM nullable_values
WHERE value IS NULL ORDER BY id;
```

| id | value | note |
| --- | --- | --- |
| 1 | NULL | NULL |

```sql
SELECT id, value FROM nullable_values WHERE value <> 10 ORDER BY id;
```

### 执行结果

| id | value |
| --- | --- |
| 2 | 0 |

示例 value <> 10 只留下 0；缺失行没有留下。可用 IS NULL 单独审计，别把 NULL 当作 0 或空字符串。

### 辨析与易错点

NOT(value=10) 不会自动包含 NULL。

空串与零仍是已知值。

关联题目：q0051、q0052、q0053、q0056、q0059

关联闪卡：fc0005、fc0007、fc0030、fc0033、fc0035

## kp05-02 IFNULL 与 COALESCE

### 核心概念

IFNULL 接受两个参数，COALESCE 返回首个非空参数；仅在业务允许时填补缺失。

### 语法

```sql
COALESCE(a,b,c); IFNULL(a,b)
```

### 执行思路

1. 检查原值
2. 仅对 NULL 采用替代值
3. 保留空文本和零

### 示例数据

nullable_values

| id | value | note |
| --- | --- | --- |
| 1 | NULL | NULL |
| 2 | 0 |  |
| 3 | 10 | ok |
| 4 | 10 | ok |

### SQL 示例

展示缺失值时可以设备用值，仍需保留有含义的零和空字符串。

IFNULL 只有两个候选；COALESCE 依次取首个非 NULL 的值。仅在 SELECT 输出处理，避免把缺失误写回源表。

```sql
SELECT id, IFNULL(value, -1) AS filled, COALESCE(note, 'missing') AS note_filled FROM nullable_values ORDER BY id;
```

### 执行结果

| id | filled | note_filled |
| --- | --- | --- |
| 1 | -1 | missing |
| 2 | 0 |  |
| 3 | 10 | ok |
| 4 | 10 | ok |

第二行的 0 和空文本都保留。若业务认为空文本也缺失，先用 NULLIF 把它转换为 NULL。

### 辨析与易错点

COALESCE 不会把空串识别为 NULL。

MySQL 返回类型推断与 SQLite 不同，混合类型需另测。

关联题目：q0054、q0058、q0060

关联闪卡：fc0031、fc0032、fc0034
