# 第08章 多表连接

阶段：核心｜学习目标：理解匹配、保留行及连接膨胀。

## kp08-01 INNER JOIN 与 ON

### 核心概念

内连接仅返回满足连接条件的行对；一个父记录匹配多个子记录会产生多行。

### 语法

```sql
FROM a INNER JOIN b ON a.key=b.key
```

### 执行思路

1. 按客户编号配对
2. 无客户的订单不返回
3. 投影编号与名称

### 示例数据

orders

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

customers

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

### SQL 示例

订单明细要展示已登记的客户姓名时，先确认只需要有匹配订单。

INNER JOIN 按 customer_id 等值匹配。左边是订单，右边客户键唯一，因此每笔有主档的订单至多匹配一行。

```sql
SELECT o.id, c.customer_name FROM orders o INNER JOIN customers c ON o.customer_id=c.customer_id ORDER BY o.id;
```

### 执行结果

| id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 林 |
| 5 | 王 |

匿名订单被省略，同一客户多笔订单仍各保留一行。若需要保留匿名订单，换成以订单为保留侧的 LEFT JOIN。

### 辨析与易错点

JOIN 默认内连接；不是把两张表按行位置拼接。

连接前确认主外键和粒度。

关联题目：q0097、q0098、q0106

关联闪卡：fc0051、fc0053

## kp08-02 LEFT JOIN 与 RIGHT JOIN

### 核心概念

左连接保留左表全部行，右表无匹配时补 NULL；右连接反向保留。

从订单向客户做 RIGHT JOIN，和交换两侧后从客户做 LEFT JOIN 保留相同客户。对客户分组时数订单的非空主键，未下单客户得到 0；数 COUNT(*) 会把补出的行算成 1。

### 语法

```sql
FROM a LEFT JOIN b ON a.key=b.key
```

### 执行思路

1. 客户1匹配两笔
2. 客户2和3各一笔
3. 客户4没有匹配，补NULL

### 示例数据

customers

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

orders

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### SQL 示例

检查客户订单覆盖时，客户主档中的未下单客户也需要显示。

LEFT JOIN 保留左侧客户，RIGHT JOIN 可通过交换左右表来表达同一关系。若要找未匹配记录，检查右表不可空键；双侧未匹配可合并两次左连接并用 UNION ALL。

**从另一侧保留全部客户**

RIGHT JOIN 的右侧是客户。计数用订单 id，未匹配的客户得到 0。

```sql
SELECT c.customer_id, COUNT(o.id) AS matched_orders
FROM orders o RIGHT JOIN customers c ON o.customer_id = c.customer_id
GROUP BY c.customer_id ORDER BY c.customer_id;
```

| customer_id | matched_orders |
| --- | --- |
| 1 | 2 |
| 2 | 1 |
| 3 | 1 |
| 4 | 0 |

```sql
SELECT c.customer_id, o.id AS order_id FROM customers c LEFT JOIN orders o ON c.customer_id=o.customer_id ORDER BY c.customer_id,o.id;
```

### 执行结果

| customer_id | order_id |
| --- | --- |
| 1 | 1 |
| 1 | 3 |
| 2 | 2 |
| 3 | 5 |
| 4 | NULL |

客户 4 的订单列为 NULL；客户 1 的重复行来自两笔订单。报告未购买客户时可进一步只保留右键为空的行。

### 辨析与易错点

RIGHT JOIN 可交换两表写成 LEFT JOIN；输出列须明确。

不要用可空业务字段判断是否匹配；使用非空主键。

关联题目：q0094、q0099、q0101、q0102、q0107、q0109

关联闪卡：fc0054、fc0057

## kp08-03 外连接的 ON 与 WHERE

### 核心概念

ON 决定匹配，WHERE 在连接完成后筛结果；对右侧字段的 WHERE 条件可能移除补 NULL 的行。

### 语法

```sql
LEFT JOIN b ON a.key=b.key AND b.flag=... 
```

### 执行思路

1. 先限制可匹配的2月订单
2. 保留全部客户
3. 统计非空订单编号

### 示例数据

customers

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

orders

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### SQL 示例

只统计二月的订单量，但仍需显示销量为零的客户。

将二月条件放在 ON 中限制匹配，再 COUNT 订单键。若在 WHERE 筛右表日期，补出的 NULL 行会被过滤。

```sql
SELECT c.customer_id, COUNT(o.id) AS feb_orders FROM customers c LEFT JOIN orders o ON c.customer_id=o.customer_id AND o.order_date >= '2026-02-01' AND o.order_date < '2026-03-01' GROUP BY c.customer_id ORDER BY c.customer_id;
```

### 执行结果

| customer_id | feb_orders |
| --- | --- |
| 1 | 1 |
| 2 | 0 |
| 3 | 1 |
| 4 | 0 |

客户 1 有一笔符合条件的订单，客户 2 为零。套用到有无某月付款的供应商时保持筛选位置。

### 辨析与易错点

同条件放 WHERE 时，无2月订单的客户可能被删除。

COUNT(*) 会把补齐行计为1。

关联题目：q0112、q0113、q0115

关联闪卡：fc0055、fc0061

## kp08-04 CROSS JOIN 与自连接

### 核心概念

交叉连接形成两表笛卡尔积；自连接使用同一表的不同别名表示不同角色。

CROSS JOIN 不用关联键，两组各有 n、m 行时返回 n×m 组配对。需要先确定是要保留某一侧记录，还是明确构造全部组合，才能选择外连接或交叉连接。

做完整门店月报时，先将门店主档与去重后的月份交叉连接，得到每店每月一行，再左接已按门店和月份聚合的交易。无交易填零前需确认该门店当月确实营业。

### 语法

```sql
FROM employees e LEFT JOIN employees m ON e.manager_id=m.employee_id
```

### 执行思路

1. 为员工表创建两个逻辑角色
2. 匹配主管编号
3. 顶层主管为空

### 示例数据

employees

| employee_id | employee_name | manager_id | salary |
| --- | --- | --- | --- |
| 1 | A | NULL | 8000 |
| 2 | B | 1 | 5000 |
| 3 | C | 1 | 5000 |
| 4 | D | 2 | 3000 |

### SQL 示例

同一张员工表包含员工和主管，要按角色读取两次。

用别名 e 和 m 区分角色，经 manager_id 匹配主键。自连接仍遵循普通的连接基数；需要构造所有组合时使用 CROSS JOIN，双侧对照还要单独考虑未匹配行。需要“仓库 × 月份”的完整报表时，先 CROSS JOIN 维度再用 LEFT JOIN 接事实表；直接连接任意明细容易制造笛卡尔积。

**生成门店月份骨架**

两个门店各配两个月，因此有四行。得到骨架后，可以在两列键上左接已汇总的月销售。

```sql
WITH stores AS (SELECT 1 AS store_id UNION ALL SELECT 2),
months AS (SELECT '2025-01' AS month_key UNION ALL SELECT '2025-02')
SELECT s.store_id, m.month_key FROM stores s CROSS JOIN months m
ORDER BY s.store_id, m.month_key;
```

| store_id | month_key |
| --- | --- |
| 1 | 2025-01 |
| 1 | 2025-02 |
| 2 | 2025-01 |
| 2 | 2025-02 |

```sql
SELECT e.employee_name, m.employee_name AS manager FROM employees e LEFT JOIN employees m ON e.manager_id=m.employee_id ORDER BY e.employee_id;
```

### 执行结果

| employee_name | manager |
| --- | --- |
| A | NULL |
| B | A |
| C | A |
| D | B |

A 的主管缺失，B 对应 A。可用同样思路配对同类商品，再加编号大小条件避免镜像及自配对。

### 辨析与易错点

CROSS JOIN 不需要匹配条件；自连接通常需要角色关联。

若交叉连接两个分别有4行和3行的表，得到12行。

关联题目：q0096、q0103、q0108、q0111

关联闪卡：fc0052、fc0057、fc0058、fc0059

## kp08-05 连接膨胀与预聚合

### 核心概念

订单与两个一对多明细直接相连，会形成明细组合，导致金额重复；先按共同键汇总再连接。

### 语法

```sql
WITH totals AS (...) SELECT ... FROM parent LEFT JOIN totals ...
```

### 执行思路

1. 按客户聚合订单
2. 确保每客户一个汇总行
3. 连接客户表

### 示例数据

customers

| customer_id | customer_name |
| --- | --- |
| 1 | 林 |
| 2 | 陈 |
| 3 | 王 |
| 4 | 李 |

orders

| id | category | sales | store_id | order_date | customer_id |
| --- | --- | --- | --- | --- | --- |
| 1 | 护肤品 | 800 | 1 | 2026-01-03 | 1 |
| 2 | 化妆品 | 400 | 2 | 2026-01-10 | 2 |
| 3 | 护肤品 | 600 | 1 | 2026-02-02 | 1 |
| 4 | 化妆品 | 300 | 2 | 2026-02-15 | NULL |
| 5 | 日用品 | 1500 | 1 | 2026-02-20 | 3 |

### SQL 示例

多笔明细同时连接会相乘，例如一位客户有两笔订单又有三次联系记录。

先按 customer_id 对订单求和，再连主档，每位客户最多匹配一行；其他明细应按相同键独立预聚合。

**按客户预聚合销售额**

```sql
WITH totals AS (SELECT customer_id,SUM(sales) AS total FROM orders WHERE customer_id IS NOT NULL GROUP BY customer_id)
SELECT * FROM totals ORDER BY 1, 2 LIMIT 3;
```

| customer_id | total |
| --- | --- |
| 1 | 1400 |
| 2 | 400 |
| 3 | 1500 |

```sql
WITH totals AS (SELECT customer_id,SUM(sales) AS total FROM orders WHERE customer_id IS NOT NULL GROUP BY customer_id) SELECT c.customer_id,COALESCE(t.total,0) AS total FROM customers c LEFT JOIN totals t ON c.customer_id=t.customer_id ORDER BY c.customer_id;
```

### 执行结果

| customer_id | total |
| --- | --- |
| 1 | 1400 |
| 2 | 400 |
| 3 | 1500 |
| 4 | 0 |

客户 1 的真实合计 1400 只出现一次。新增联系次数时可接一张客户粒度的汇总，避免销售额倍增。

### 辨析与易错点

DISTINCT 金额会错误合并不同交易的相同金额。

缺订单是否可视为0须由业务定义。

关联题目：q0095、q0114、q0116、q0117、q0118

关联闪卡：fc0056、fc0060
